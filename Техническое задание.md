# Техническое задание

## Онлайн-платформа курсов по искусственному интеллекту

**Дата составления:** 21.08.2026
**Версия документа:** 1.0 (черновик)

---

## 1. Общее описание проекта

### 1.1. Суть проекта

Разрабатывается веб-платформа для обучения людей практическому применению
искусственного интеллекта в их профессиональной деятельности и повседневных
задачах. Платформа объединяет каталог видеокурсов, систему прохождения
обучения, практические задания и сообщество пользователей.

В отличие от общих IT-образовательных платформ, фокус — исключительно на
**прикладном использовании AI-инструментов** в разных профессиях и сферах:
не "как работают нейросети изнутри", а "как конкретно применить их в своей
работе уже завтра".

### 1.2. Примеры направлений курсов

| Направление | Пример курса |
|---|---|
| Видео и монтаж | Использование нейросетей для апскейла, шумоподавления, генерации b-roll, автоматических субтитров, цветокоррекции |
| Бизнес и стратегия | Разработка стратегий развития компании с помощью AI, анализ рынка через LLM, автоматизация процессов |
| Маркетинг | Генерация рекламных креативов, копирайтинг с AI, персонализация коммуникаций |
| Дизайн | Генерация изображений, ускорение прототипирования (Midjourney, Stable Diffusion и др.) |
| Разработка | AI-ассистенты в программировании, автоматизация тестирования |
| Личная продуктивность | Автоматизация рутины, работа с AI-ассистентами и агентами |

Список направлений открытый и должен расширяться без изменения архитектуры
платформы (см. п. 4.3 — управление каталогом курсов).

Для пилотного запуска (Этап 1) готовятся **2 курса-заглушки** (структура
курса заполнена, содержание — плейсхолдер, наполняется позже):

1. **"AI в видеомонтаже"** — направление "Видео и монтаж".
2. **"AI для разработчиков"** — направление "Разработка".

### 1.3. Референс по дизайну и UX

Визуальный и UX-ориентир — **Udemy**: сетка карточек курсов в каталоге
(превью, рейтинг, автор, метка "бесплатно"/цена), страница курса с
программой в виде раскрывающихся модулей/уроков, блоком "чему вы
научитесь", отзывами и информацией об авторе; личный кабинет со списком
"мои курсы" и прогресс-барами. Точная айдентика (логотип, цветовая схема,
шрифты) прорабатывается отдельно на этапе дизайна — здесь фиксируется
только структурный/UX-паттерн.

### 1.4. Целевая аудитория

- Специалисты, желающие внедрить AI-инструменты в свою профессию (монтажёры,
  маркетологи, дизайнеры, предприниматели, менеджеры).
- Владельцы малого и среднего бизнеса, ищущие стратегии роста с применением AI.
- Новички, не имеющие технического бэкграунда, но желающие освоить
  инструменты на пользовательском уровне.

### 1.5. Цели проекта

1. Дать пользователям структурированные практические знания по применению AI
   в конкретных задачах.
2. Создать удобную среду для прохождения курсов: текстовые материалы с
   изображениями, задания, сертификаты. Видеоформат уроков — задел на
   будущее, при расширении серверных мощностей (см. п. 9).
3. Обеспечить монетизацию через продажу курсов/подписок (после пилотного
   периода — см. п. 9).
4. Заложить масштабируемую архитектуру для роста каталога и аудитории.

## 2. Роли пользователей

| Роль | Описание |
|---|---|
| **Гость** | Неавторизованный посетитель. Видит каталог, описания курсов, лендинги, отзывы. |
| **Студент** | Зарегистрированный пользователь. Покупает/получает доступ к курсам, проходит уроки, выполняет задания, получает сертификаты. |
| **Автор курса / преподаватель** | Внутренний сотрудник платформы (разработчик курсов). Внешних/сторонних авторов и маркетплейс-модели нет. Создаёт и редактирует курсы, загружает материалы, вручную проверяет задания, общается со студентами. |
| **Модератор** | Модерирует отзывы, комментарии, вопросы в поддержке. В MVP как отдельная роль не выделяется — функции временно выполняет Администратор (см. п. 9). |
| **Администратор** | Полный доступ: управление пользователями, курсами, платежами, контентом, аналитикой, настройками платформы. Роль обязательна с первого дня (подтверждено заказчиком). |

## 3. Пользовательские сценарии (Use Cases)

1. Гость заходит на платформу, просматривает каталог курсов, фильтрует по
   направлению ("монтаж", "бизнес", "маркетинг"), открывает карточку курса.
2. Гость регистрируется / входит через email или соцсети.
3. Студент получает доступ к курсу (в пилотном периоде — бесплатно для всех
   зарегистрированных пользователей; оплата/подписка добавляются позже —
   см. п. 9).
4. Студент проходит уроки: читает текстовые материалы с изображениями,
   выполняет практические задания, отвечает на тесты.
5. Студент отслеживает прогресс по курсу (% пройденного, пройденные модули).
6. Студент получает сертификат после завершения курса.
7. Студент задаёт вопросы преподавателю / в общем чате курса.
8. Студент оставляет отзыв и оценку курсу.
9. Автор курса создаёт новый курс через панель управления: структура →
   модули → уроки → материалы → задания → публикация.
10. Администратор просматривает аналитику продаж, активности, отзывы,
    управляет ценами и промокодами.

## 4. Функциональные требования

### 4.1. Регистрация и аутентификация

- Регистрация и вход только по email/паролю. Вход через Google/соцсети
  (OAuth2) — не входит в MVP, добавляется позже при необходимости
  (см. п. 9).
- Подтверждение email.
- Восстановление пароля.
- Личный кабинет пользователя (профиль, аватар, история покупок, прогресс).

### 4.2. Каталог курсов

- Список курсов с фильтрацией по направлению, уровню сложности
  (начинающий/средний/продвинутый), цене, длительности, рейтингу.
- Поиск по названию и ключевым словам.
- Карточка курса: описание, программа (список модулей/уроков), автор,
  отзывы, рейтинг, требования "что нужно знать перед началом". Стоимость
  отображается, когда включена монетизация (не в MVP — см. п. 9).
- Бесплатный вводный урок / демо-урок для привлечения аудитории.

### 4.3. Управление курсами (для авторов/администраторов)

- Конструктор курса: создание модулей и уроков, drag-n-drop сортировка.
- Контент урока — текст (rich text/markdown) с изображениями (загрузка
  картинок, скриншотов, схем). Видео как формат урока в MVP не
  поддерживается (см. п. 9); при необходимости внешнее видео можно
  добавить как встроенную ссылку (YouTube/Vimeo-embed), это не требует
  ресурсов собственного сервера.
- Прикрепление доп. материалов: PDF, ссылки, шаблоны, чек-листы.
- Создание практических заданий: текстовый ответ, загрузка файла, тест с
  выбором ответа. Проверка — ручная, силами автора курса (см. п. 9).
- Публикация/снятие с публикации, черновики, версионирование.

### 4.4. Прохождение курса

- Просмотр контента урока: текст с изображениями (без видеоплеера в MVP).
- Отслеживание прогресса (пройдено/не пройдено по каждому уроку).
- Практические задания и тесты с проверкой результата.
- Конспекты/заметки пользователя внутри урока.
- Обсуждения/вопросы под уроком (Q&A с автором курса или сообществом).

### 4.5. Сертификация

- Автоматическая генерация сертификата (PDF) при выполнении условий
  завершения курса (например, ≥ 80% заданий).
- Уникальный проверочный код/ссылка для подтверждения подлинности
  сертификата.

### 4.6. Оплата и монетизация

> **Не входит в MVP.** В пилотном периоде доступ ко всем курсам бесплатный
> для зарегистрированных пользователей. Раздел описывает функциональность
> следующего этапа, после того как платформа будет обкатана и вопрос
> монетизации будет решён отдельно (регион, провайдер — см. п. 9).

- Разовая покупка отдельного курса.
- Подписочная модель (доступ ко всему каталогу на месяц/год).
- Промокоды и скидки.
- Интеграция с платёжными системами (эквайринг, ЮKassa/Stripe/др. — уточнить
  у заказчика в зависимости от региона).
- История платежей, чеки, возвраты.

### 4.7. Отзывы и рейтинги

- Оценка курса (звёзды) и текстовый отзыв после прохождения (или частичного
  прохождения).
- Модерация отзывов.

### 4.8. Уведомления

- Email-уведомления: подтверждение покупки, напоминания о продолжении
  курса, новости о новых курсах.
- Внутриплатформенные уведомления (колокольчик).

### 4.9. Административная панель

- Управление пользователями (блокировка, роли, доступы).
- Управление курсами и категориями.
- Финансовая аналитика: продажи, конверсия, LTV.
- Управление промокодами и ценами.
- Модерация отзывов и комментариев.

### 4.10. Сообщество (опционально, для расширения)

- Общий чат/форум по направлениям.
- Личный кабинет с достижениями/бейджами за прогресс.

## 5. Нефункциональные требования

- **Производительность:** загрузка страницы каталога — не более 2 секунд
  при типовом соединении; учитывать ограниченные ресурсы текущего сервера
  (см. п. 6, п. 9) — избегать тяжёлых фоновых процессов в MVP.
- **Масштабируемость:** архитектура должна выдерживать рост каталога и
  аудитории без переписывания ядра; при появлении видео как формата
  контента — миграция хранения медиа на объектное S3-хранилище + CDN без
  изменения структуры уроков.
- **Безопасность:** защита персональных данных (152-ФЗ/GDPR — уточнить
  юрисдикцию); платежи в MVP отсутствуют, требования по PCI DSS
  становятся актуальны на этапе подключения оплаты.
- **Доступность:** адаптивная вёрстка (desktop/tablet, mobile-приложение не
  требуется на первом этапе — см. п. 9), базовое соответствие WCAG.
- **Локализация:** русский язык — основной, архитектура должна
  предусматривать возможность добавления других языков.
- **Резервное копирование:** ежедневный бэкап БД и загруженных изображений.
- **SEO:** карточки курсов и лендинги должны индексироваться поисковиками
  (SSR/пререндер для публичных страниц).

## 6. Технологический стек

Архитектура — монолит: единый backend-сервис на Django, фронтенд —
отдельное SPA-приложение, обращающееся к backend по REST API.

- **Backend:** Python, Django + Django REST Framework. Выбор в пользу
  Django (а не FastAPI/Flask) обоснован тем, что платформе с первого дня
  нужны встроенная аутентификация, ORM с миграциями и готовая
  административная панель — это ускоряет реализацию MVP (управление
  курсами, ролями, модерацией).
- **Frontend:** React + Vite, SPA. Деплоится как статика, отдельный
  Node-сервер для рендеринга не требуется. SEO публичных страниц
  (каталог, лендинги курсов) в MVP не обеспечивается за счёт SSR;
  при необходимости решается точечно (пререндер отдельных лендингов) —
  вынесено в открытые вопросы (п. 9).
- **База данных:** PostgreSQL.
- **Хранение медиа (MVP — только изображения):** локальное файловое
  хранилище на сервере (Django `MEDIA_ROOT`), без видео, без
  транскодирования, без CDN — сервер под проект слабый, лишняя
  инфраструктура не нужна на этом этапе. При росте нагрузки или
  добавлении видео — миграция на S3-совместимое объектное хранилище
  + CDN (архитектура это допускает без переделки модели данных, см. п. 5).
- **Очереди/фоновые задачи:** в MVP не требуются (нет видео-обработки,
  объём писем небольшой — отправляются синхронно). Celery + Redis
  добавляются на следующем этапе при росте нагрузки или подключении
  оплаты/уведомлений в объёме.
- **Аутентификация:** Django auth на бэкенде, JWT
  (djangorestframework-simplejwt) для взаимодействия с SPA. Только
  email/пароль в MVP — OAuth2 (Google/соцсети) не входит в MVP,
  добавляется позже при необходимости.
- **Платежи:** не входит в MVP (см. п. 4.6, п. 9). При подключении —
  платёжный шлюз (ЮKassa/CloudPayments/Stripe, по региону), без хранения
  данных карт на платформе.
- **Инфраструктура:** Docker, CI/CD, один backend-сервис (монолит) на
  имеющемся сервере + статический фронтенд, раздаваемый тем же
  веб-сервером (Nginx). Минимальные требования к ресурсам за счёт
  отсутствия видео и фоновых очередей в MVP.

### 6.1. Характеристики сервера (текущий, для MVP)

- CPU: 4 ядра
- RAM: 4 ГБ
- Диск: 50 ГБ

Этих ресурсов достаточно для монолита на Django + PostgreSQL + Nginx с
контентом "текст + изображения" без видео и без фоновых очередей — выбор
стека в этом разделе уже сделан с учётом данных ограничений. Диск (50 ГБ)
делится между БД, загруженными изображениями и системными нуждами;
при заметном росте объёма изображений или переходе на видео потребуется
либо увеличение диска, либо вынос медиа во внешнее хранилище (см. выше).

## 7. Структура данных (укрупнённо)

- **User** (id, email, роль, профиль, дата регистрации)
- **Course** (id, название, описание, направление, уровень, цена, автор,
  статус публикации)
- **Module** (id, course_id, порядок, название)
- **Lesson** (id, module_id, порядок, текстовый контент, изображения)
- **Assignment** (id, lesson_id, тип задания, статус ручной проверки)
- **Enrollment** (user_id, course_id, дата получения доступа, прогресс,
  статус)
- **Payment** (id, user_id, сумма, статус, тип — курс/подписка) —
  задел на будущее, не используется, пока не подключена оплата (см. п. 9)
- **Review** (id, user_id, course_id, оценка, текст, статус модерации)
- **Certificate** (id, user_id, course_id, дата выдачи, код проверки)

## 8. Этапы разработки (предложение по MVP)

### Этап 1 — MVP (пилот)
- Регистрация/авторизация.
- Каталог курсов: 2 курса-заглушки для старта ("AI в видеомонтаже",
  "AI для разработчиков") — структура заполнена, контент наполняется
  отдельно после готовности платформы.
- Уроки в текстовом формате с изображениями + отслеживание прогресса.
- Практические задания с ручной проверкой автором курса.
- Бесплатный доступ ко всем курсам для зарегистрированных пользователей
  (оплаты нет).
- Простая админ-панель для загрузки курсов (создатели курсов — только
  внутренняя команда).

### Этап 2 — по итогам пилота
- Подключение оплаты: разовая покупка и/или подписка (провайдер и модель —
  по итогам пилота, см. п. 9).
- Сертификаты.
- Отзывы и рейтинги.
- При необходимости — переход на очереди (Celery/Redis) и облачное
  хранилище медиа.

### Этап 3
- Сообщество/чат/форум.
- Расширенная аналитика для администратора.
- Промокоды, реферальная программа.
- Видеоуроки — при расширении серверных мощностей или переезде на внешнее
  видеохранилище/CDN.
- Мобильная адаптация/PWA (или отдельное приложение — по решению).

## 9. Решённые и открытые вопросы

### Решено (зафиксировано заказчиком, 21.08.2026)

1. **Оплата** — не входит в MVP. Пилотный период: доступ ко всем курсам
   бесплатный. Выбор платёжного провайдера, региона и юрисдикции по
   персональным данным — решается после обкатки платформы, отдельным
   этапом (см. п. 4.6, Этап 2).
2. **Модель авторства** — только внутренние авторы платформы (штатная
   команда разработки курсов). Маркетплейса с внешними авторами не будет.
3. **Мобильная версия** — не нужна на первом этапе. Веб-версии
   (адаптивной вёрстки) достаточно.
4. **Проверка заданий** — ручная, силами автора курса. Автоматическая
   проверка не предусмотрена в MVP.
5. **Инфраструктура/видео** — текущий сервер слабый, поэтому self-hosted
   обработка видео исключена. В MVP поддерживается только текстовый
   контент с изображениями. Видео как формат — задел на будущее, при
   расширении мощностей сервера или переходе на внешнее
   хранилище/видеохостинг (см. Этап 3, п. 6).
6. **Дизайн/UX** — визуальный ориентир: Udemy (см. п. 1.3). Точная
   айдентика — отдельная задача дизайна.
7. **Контент для старта** — 2 курса-заглушки: "AI в видеомонтаже" и
   "AI для разработчиков" (см. п. 1.2). Наполнение — отдельная задача,
   не блокирует разработку платформы.
8. **Аналитика** — не нужна в MVP: ни финансовая (оплаты нет), ни
   поведенческая (GA/Яндекс.Метрика). Достаточно данных из БД при
   необходимости разовых отчётов.
9. **Сервер** — 4 CPU / 4 ГБ RAM / 50 ГБ диск (см. п. 6.1). Стек и объём
   функциональности MVP подобраны под эти ограничения.
10. **Способ входа** — только email/пароль. OAuth2 (Google/соцсети) не
    входит в MVP (см. п. 4.1, п. 6).
11. **Роль "Модератор"** — отдельно в MVP не выделяется, её функции
    выполняет Администратор (см. п. 2).
12. **Пользовательское соглашение / политика конфиденциальности** — в
    MVP не разрабатываются. *Замечание:* платформа всё равно собирает
    персональные данные при регистрации (email), поэтому перед публичным
    запуском (не в закрытом пилоте) эти документы, как правило, нужны по
    закону (152-ФЗ) — риск сознательно принят на пилотный период, вопрос
    можно вернуть к рассмотрению перед открытием доступа внешним
    пользователям.

### Остаётся открытым

- Конкретные параметры платёжной интеграции и юрисдикция — к моменту
  подключения оплаты (Этап 2).
- Формат видео при последующем внедрении: self-hosted (S3 + CDN +
  транскодирование) против embed-ссылок на внешний хостинг (YouTube/
  Vimeo) — второй вариант почти не требует ресурсов сервера и может быть
  добавлен раньше, если понадобится видео до апгрейда инфраструктуры.
