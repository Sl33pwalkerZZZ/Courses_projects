# Recording Checklist — Real CapCut Desktop Operations

## Before opening the recorder

- [ ] Confirm the author-approved script and storyboard revision for the selected video.
- [ ] Record actual CapCut Desktop product version/build, operating system and interface language. Do not infer these from prior screenshots or another computer.
- [ ] Record the actual screen-capture tool/version and capture settings. The project does not require OBS; use only an available, approved capture method.
- [ ] Use an isolated demo user/project and copied media. Preserve originals. No personal files, private user folders, browser accounts, notifications, access tokens, real university identifiers or student records may appear.
- [ ] Prepare the fictional F1 media package and source/permission notes. Leave any unverified permission field blank/unconfirmed.
- [ ] Check screen size/readability, pointer position, recording storage and free space. Do a short test capture and confirm it decodes.
- [ ] For V2, prove the real build can create a separate working copy and set a 9:16 project/canvas. If either operation is not supported/available, stop and request an approved storyboard revision.

## During capture

- [ ] Capture only genuine operations in the actual CapCut Desktop application for any screen labeled as CapCut.
- [ ] Keep the real version/workspace visible where practical; hide only private information, not relevant warnings, limitations or errors.
- [ ] Capture enough lead-in/lead-out around each operation for editing; pause after each setting change so its result is readable.
- [ ] Use real control names as displayed. Do not narrate a guessed button label. If a UI differs, record the difference and correct the script before final narration.
- [ ] Do not conceal missing operations with a cut or Remotion animation. If a capture is interrupted or the application fails, disclose/re-record that part.
- [ ] For exports, show the actual local output path in a sanitized demo directory, actual completion and actual resulting file. Do not enter a publish/share flow.
- [ ] For V3, distinguish the actual exported file from Remotion-made fictional examples and checklist graphics.
- [ ] Capture the actual caption/subtitle verification route used; no fake text track or fabricated result.

## After capture

- [ ] Preserve original screen-capture file unchanged; compute SHA-256 and write a separate capture log.
- [ ] Review the whole capture for privacy leakage, incorrect claims, cut-off text, missed operation, visible errors and silent/inaudible sections.
- [ ] Confirm that every statement about output settings, project state and source permissions is evidenced by the real capture or a verified record.
- [ ] Save the native CapCut project and all linked files using the actual format/path created by the installed version. Reopen it in that environment and confirm editability.
- [ ] Prepare a proxy/edit copy if required; never transcode or overwrite the preserved original capture.
- [ ] Only after raw capture review, add voice, Remotion diagrams and captions in the isolated production package.

## Stop conditions

Stop and ask for direction if CapCut Desktop is unavailable, the required control cannot be verified, app version/OS cannot be recorded, the demo exposes private data, the export does not match the intended demonstration, or permission for any included visual/voice/font is unclear.
