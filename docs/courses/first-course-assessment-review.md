## 1. Какое описание точнее отражает понятие искусственного интеллекта?
Тип: single

- **A.** Системы для задач, обычно требующих интеллектуальных способностей человека.
- **B.** Только программы, создающие изображения.
- **C.** Система, которая обязательно мыслит так же, как человек.
- **D.** Любой электронный документ.

Правильные варианты: A

Объяснение: Раздел 1.1 определяет ИИ через выполняемые задачи; человеческий способ мышления не является обязательным.

## 2. Какие утверждения о связи ИИ, ML, Deep Learning и LLM соответствуют главе?
Тип: multiple

- **A.** Машинное обучение является направлением ИИ.
- **B.** Глубокое обучение основано на многослойных нейронных сетях.
- **C.** LLM — один из классов моделей глубокого обучения.
- **D.** Генеративный ИИ ограничивается только LLM.

Правильные варианты: A, B, C

Объяснение: Раздел 1.1 описывает вложенную связь направлений. Генеративный ИИ также включает модели изображений, звука и других типов.

## 3. Что означает машинное обучение в описании главы?
Тип: single

- **A.** Система извлекает закономерности из данных.
- **B.** Разработчик вручную записывает ответ для каждой ситуации.
- **C.** Пользователь обязательно обучает модель при каждом запросе.
- **D.** Любой ответ автоматически становится проверенным фактом.

Правильные варианты: A

Объяснение: ML использует данные для обнаружения закономерностей; это отличается от набора готовых правил для каждой ситуации.

## 4. Какова упрощённая последовательность работы LLM?
Тип: single

- **A.** Запрос → токены и контекст → вычисления модели → генерация → результат.
- **B.** Запрос → гарантированная проверка фактов → готовая истина.
- **C.** Ответ → запрос → загрузка лицензии → обучение пользователя.
- **D.** Запрос → обязательный поиск в интернете → ручной ответ оператора.

Правильные варианты: A

Объяснение: Раздел 1.2 описывает последовательную генерацию токенов. Наличие веб-поиска зависит от подключённых инструментов сервиса.

## 5. Какие ограничения LLM нужно учитывать?
Тип: multiple

- **A.** Возможны убедительные, но неверные утверждения.
- **B.** Контекст обращения ограничен.
- **C.** Сведения могут устареть без внешних источников.
- **D.** Модель гарантирует существование каждой приведённой ссылки.

Правильные варианты: A, B, C

Объяснение: В разделе 1.2 перечислены галлюцинации, ограниченный контекст и актуальность. Убедительный ответ не заменяет проверку.

## 6. Модель привела убедительную ссылку. Как следует отнестись к ней?
Тип: single

- **A.** Независимо проверить существование источника и соответствие утверждению.
- **B.** Считать ссылку достоверной из-за уверенного тона.
- **C.** Предполагать, что все модели всегда используют текущий веб-поиск.
- **D.** Удалить требования к точности, чтобы не замедлять работу.

Правильные варианты: A

Объяснение: Сценарий — авторское учебное дополнение. Он применяет предупреждение главы о галлюцинациях и необходимости проверки источников.

## 7. В чём состоит различие модели и сервиса?
Тип: single

- **A.** Модель обрабатывает запрос, а сервис предоставляет интерфейс и рабочие функции.
- **B.** Сервис и модель всегда являются одним и тем же объектом.
- **C.** Модель используется только без программирования.
- **D.** Сервис не может подключать файлы или другие инструменты.

Правильные варианты: A

Объяснение: Раздел 1.3 разделяет вычислительную модель и готовый продукт, который может предоставлять дополнительные инструменты.

## 8. Какие утверждения о моделях и сервисах верны?
Тип: multiple

- **A.** Один сервис может предлагать несколько моделей.
- **B.** Одна модель может применяться в разных продуктах.
- **C.** Возможности сервиса определяются только названием модели.
- **D.** Модель никогда не предоставляется через API.

Правильные варианты: A, B

Объяснение: Глава прямо указывает на связь «многие ко многим» и различает характеристики модели, функций и интеграций сервиса.

- **C.** Только создание иллюстраций.
- **D.** Управление публикацией курса.

Правильные варианты: A

Объяснение: Таблица раздела 1.4 относит транскрибацию и распознавание речи к инструментам речи и аудио. Категории могут пересекаться в мультимодальных продуктах.

## 10. Что важно помнить при сравнении сервисов из обзора?
Тип: multiple

- **A.** Функции могут зависеть от плана, лицензии и настроек.
- **B.** Источники поисковых ответов нужно проверять независимо.
- **C.** Один известный бренд автоматически является лучшим для любой задачи.
- **D.** Любая учётная запись гарантирует одинаковые интеграции.

Правильные варианты: A, B

Объяснение: Раздел 1.5 содержит оговорки о доступности возможностей и предупреждение против универсального рейтинга «лучший для всех».

Тип: single

- **D.** С передачи всех рабочих документов в случайный сервис.

Правильные варианты: A

Объяснение: Первый шаг раздела 1.6 — постановка задачи. Инструменты выбирают после определения результата и требований.

## 13. Как корректно провести сравнительное тестирование?
Тип: multiple

- **A.** Применить одинаковые обезличенные исходные данные.
- **B.** Заранее задать общие критерии качества, скорости и ошибок.
- **C.** Каждому сервису дать принципиально разные задания.
- **D.** Выбирать только по длине ответа без проверки содержания.

Правильные варианты: A, B

Объяснение: Шаг 4 требует сопоставимых примеров и единых критериев. Иначе различия результата нельзя обоснованно связать с выбранным инструментом.

## 14. Как учитывать расходы при выборе сервиса?
Тип: single

- **A.** Проверить подписку и возможную отдельную оплату API вместе с другими критериями.
- **B.** Считать любой API включённым в подписку по умолчанию.
- **C.** Использовать цену как единственный показатель качества.
- **D.** Не учитывать расходы, если сервис популярен.

Правильные варианты: A

Объяснение: Шаг 3 отдельно называет подписку и возможные API-расходы; решение также учитывает качество, функции, скорость, безопасность и удобство.

## 15. Что делать при работе с внутренними или конфиденциальными данными?
Тип: single

- **A.** Проверить разрешение и правила обработки; для сравнения использовать обезличенные образцы.
- **B.** Отправить реальные секретные данные каждому сервису ради одинакового теста.
- **C.** Предположить, что все внешние сервисы автоматически разрешены организацией.
- **D.** Записать пароль в карту выбора, чтобы подтвердить доступ к сервису.

Правильные варианты: A

Объяснение: Практический пример раздела 1.7 требует разрешения или обезличивания. Для конфиденциальных данных раздел 1.6 допускает необходимость корпоративной инфраструктуры или локальных моделей.

## Проверка до публикации

- Проверить формулировки и покрытие целей, отвлекающие варианты, все правильные ответы и объяснения.
- Проверить актуальность названий моделей/сервисов, тарифов, API-расходов, функций файлов/поиска/Deep Research и интеграций. В исходной главе нет точных цен; не добавлять неподтверждённые цены.
- Проверить доступность и лицензирование по региону/учётной записи, правила хранения и использования данных.
- Проверить все исходные ссылки; адрес prompt-ingineering в источнике может содержать опечатку. Исходный адрес сохранён, а не молча заменён.
- Подтвердить, что это только глава 1. Упоминание следующего занятия об ИИ-агенте сохранено, нового содержания нет.
- После согласования администратор отдельно подтверждает review_approved и вручную публикует курс/тест. Импорт ничего не публикует.
