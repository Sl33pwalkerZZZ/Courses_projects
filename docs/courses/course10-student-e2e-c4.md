## Дополнительные проверки через настоящий HTTP API

Эти проверки **не выдаются за отдельные пользовательские UI-действия**:

- Собственные попытки Quiz5: две записи, 10/15 false и 11/15 true; API истории и UI согласованы. До отправки в API вопросов нет `is_correct`, ключей или объяснений; раскрытие результатов собственной попытки соответствует существующим правилам.
- Две версии проекта: rejected → approved, вторая ссылается на первую; четыре оценки и история проверки сохранены. Собственные файлы обеих версий скачиваются с 200 и `private, no-store`.
- Все 11 невидео-вложений (4 audio, 2 SRT, 5 VTT) и 7 изображений получены авторизованным студентом через API: 200, SHA-256 байтов совпадает с копиями в защищённом хранилище.
- Второй зачисленный студент: собственная пустая история, собственный прогресс 0/16; чужая попытка теста **404**, чужой файл проекта **404**, попытка проверки работы через Studio **403**.
- Незачисленный студент: CourseDetail черновика **404**, урок/тест/отправки/вложение/создание grant **403**. Чужой scoped playback URL без соответствующей cookie также **403**.
- Анонимные запросы к уроку, файлу работы, попытке теста и обычному защищённому вложению: **401**.
- Grant отдельной проверочной сессии: создание **200**, `Range: bytes=0-99` → **206**, Content-Length 100; DELETE → **204**, следующий Range → **403**. Действующие студенческие плееры не получали исходный непреднамеренный 403. Полный искусственно задержанный race-тест C3.1 заново не повторялся.
- Отключённые сертификаты: certificate-status **404** с `Certificates are not enabled.`, issuance POST **404**, собственный список **200 []**. Число сертификатов синтетического студента курса 10 осталось **0**. Служебный 404 отключённой функции не является неисправностью.
- ORM и SQLite в копии подтверждают: 16 отметок прохождения, обе попытки и обе версии проекта, корректную связь версий, отсутствие сертификата. `integrity_check=ok`, foreign-key violations=0.

Независимый native `security_reviewer` выполнил read-only обзор маршрутов/ownership/оценивания/сертификатов. Блокеров в просмотренных путях не нашёл; фактические HTTP-результаты выше получены основным прогоном, не подменены статическим обзором.

## Обнаруженное замечание, без исправления

**P2 — отзывы в обзоре доступного студенту черновика.**

1. Войти зачисленным синтетическим студентом, открыть `/courses/ai-media-content` при `is_published=False`.
2. CourseDetail успешно загружается, уроки и программа доступны.
3. `GET /api/courses/ai-media-content/reviews/` возвращает **404**; интерфейс показывает «Не удалось загрузить отзывы. Попробуйте снова».
4. Причина установлена: `CourseDetail.jsx:149` безусловно монтирует CourseReviews, тогда как `reviews/views.py:22–23` намеренно ищет только опубликованные курсы. Существующий тест `reviews/tests.py:test_draft_and_missing_courses_are_not_exposed` закрепляет это ограничение.
5. Минимальное предложение для отдельного согласованного изменения: отображать недоступность отзывов для такого случая, без бесполезного retry и без ослабления серверного фильтра публикации. Сетевые/прочие ошибки должны оставаться ошибками. Код в C4 не менялся.

Это не блокирует обучение или аттестацию. Других подтверждённых блокеров в выполненном сценарии нет. Полный перебор ролей, всех комбинаций загрузок, мобильных размеров и RU/KK/EN в C4 не выполнялся; прежние проверки не объявляются новыми результатами.
