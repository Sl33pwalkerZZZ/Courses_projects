## Применение к существующему курсу после отдельного разрешения

Не запускать create-only import_media_module/import_media_module_6 поверх существующего курса: они отвергают конфликты, не являются обновляторами.

```bash
.venv/bin/python -B manage.py correct_course10_editorial --dry-run
.venv/bin/python -B manage.py correct_course10_editorial --apply --backup-dir .local-course-backups/course10-c1
.venv/bin/python -B manage.py correct_course10_editorial --dry-run
```

Здесь выполнен только dry-run против рабочей БД, через принудительно read-only настройки. Apply выше НЕ выполнен. Команда проверяет exact before/after и неопубликованный Course10, резервирует запись SQLite, повторяет проверки, создаёт/проверяет backup API-копию и атомарно применяет изменения. Любой конфликт/ошибка откатывает транзакцию. Метаданные целей, Quiz5, сертификатная политика, отметки Studio, заявки, медиа и другие курсы не записываются. Перед рабочим запуском остановить редактирование/прочие записи, проверить4ожидаемых поля и затем сохранить проверенный backup вне Git. При откате не восстанавливать всю БД поверх новых студенческих данных; использовать проверенную копию и отдельное согласование точечного отката.
