## Реализация

В существующем редакторе урока добавлена форма «заголовок + текст» и кнопка добавления раздела. Она обновляет только текущий черновик text_content и learning_content.source_sections. Сохранение проходит через прежний atomic lesson PATCH; новых моделей, полей API, маршрутов или миграций нет.

Новые разделы добавляются в конец в том же порядке, что и абзацы основного текста. Если в обычном уроке уже есть текст, первый новый заголовок явно ставится перед ним; введённый ранее текст остаётся внутри первого раздела, новый текст добавляется после него. Интерфейс заранее объясняет эту конверсию. Никакие существующие абзацы автоматически не распознаются как заголовки.

Пустые, многострочные, повторяющиеся заголовки, совпадения с отдельным абзацем или неразрешённым медиа-якорем отклоняются. Новому разделу нужен текст; первый раздел может использовать уже введённый основной текст. Ограничение100 разделов соответствует текущему сериализатору. Клиент и сервер проверяют согласованность новых якорей; сервер не позволяет случайно привязать осиротевшее вложение/изображение новым заголовком.

Существующие разделы/порядок и медиа сохраняются. Переименование и добавление в одном сохранении поддерживаются; прежнее переименование обновляет связанные видео/субтитры атомарно. Новые якоря доступны загрузчику вложений после сохранения урока. Удаление и перестановка через этот UI не добавлялись. Серверная валидация прежних metadata-only операций без новых якорей не ужесточалась ретроактивно.

Промежуточные поля section_new остаются только в локальном черновике: участвуют в dirty-confirmation и сохранении более нового ввода после ответа PATCH, не отправляются как отдельные поля API. Пока заполненный новый раздел не добавлен либо не очищен, основное сохранение заблокировано с пояснением. Plain-text уроки сохраняются прежним способом. Legacy-идентификаторы и уроки с дополнительными teaching interactions остаются в существующем редакторе: добавление разделов для них отклоняется понятным сообщением, поскольку текущий student renderer не поддерживает такой гибрид.

Использован существующий Chromium (без установки браузеров). Playwright MCP Firefox остаётся недоступен по результату предшествующего прохода. На этом этапе root-agent управлял обычным приложением, native inputs/buttons/confirm и настоящими HTTP API; никаких mock/adapter и ручного API-добавления source_sections не было. Фактически выполнено:

1. UI login → создать черновик курса1, модуль1, урок1 в отдельной БД.
2. Ввести и сохранить исходный обычный текст. Проверить stay/discard при изменении текста.
3. Через кнопку добавления проверить ошибку пустого заголовка. Заполнить поля первого раздела; переход в другую вкладку вызывает confirm, отказ сохраняет поля.
4. Добавить «Подготовка», затем проверить отклонение повторного заголовка без потери первого раздела; исправить на «Проверка» и добавить второй раздел.
5. Сохранить → заново открыть страницу/урок. Обе строки source_sections и полный текст подтверждены; старый вводный абзац сохранён в первом разделе.
6. Через UI загрузить оригинальный синтетическийSRT и выбрать сохранённую «Подготовку».
7. Дополнительный regression: переименовать её в «Подготовка материалов», сохранить, затем переместитьSRT в «Проверка». ID/имя/байты вложения сохраняются.
